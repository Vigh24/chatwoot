# Deploying Chatwoot to Render

This guide will help you deploy Chatwoot v4.3.0 to Render with full pgvector support for AI features.

## Why Render?

Render provides several advantages over Railway for Chatwoot deployment:

- ✅ **Native pgvector support** - PostgreSQL 16 with pgvector extension included
- ✅ **Reliable infrastructure** - Better uptime and performance
- ✅ **Automatic SSL certificates** - HTTPS enabled by default
- ✅ **Built-in monitoring** - Health checks and metrics
- ✅ **Predictable pricing** - No surprise bills
- ✅ **Easy scaling** - Simple horizontal and vertical scaling

## Prerequisites

- Render account (free tier available)
- GitHub repository with your Chatwoot code
- Basic understanding of environment variables

## Quick Deployment (Recommended)

### Step 1: Fork or Clone Repository

If you haven't already, ensure your code is in a GitHub repository.

### Step 2: Deploy to Render

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click "New" → "Blueprint"
3. Connect your GitHub repository
4. Render will automatically detect the `render.yaml` file
5. Click "Apply" to start deployment

### Step 3: Configure Environment Variables

The `render.yaml` file includes most configurations, but you may want to customize:

**Required customizations:**
- `MAILER_SENDER_EMAIL`: Your email address for notifications
- `SMTP_*` variables: Your email service configuration
- `FRONTEND_URL`: Will be auto-generated, but you can use a custom domain

**Optional customizations:**
- `ENABLE_ACCOUNT_SIGNUP`: Set to "true" if you want public signups
- `DEFAULT_LOCALE`: Change from "en" if needed

### Step 4: Wait for Deployment

- Web service: ~10-15 minutes for first deployment
- Database: ~5-10 minutes to provision
- Redis: ~2-3 minutes to provision

### Step 5: Verify Deployment

1. Check the web service logs for successful startup
2. Look for "✅ pgvector extension is available!" message
3. Visit your app URL to confirm it's working

## Manual Deployment (Alternative)

If you prefer to set up services manually:

### Step 1: Create PostgreSQL Database

1. In Render Dashboard, click "New" → "PostgreSQL"
2. Configure:
   - **Name**: `chatwoot-postgres`
   - **Database**: `chatwoot`
   - **User**: `chatwoot`
   - **Region**: Choose closest to your users
   - **Plan**: Starter ($7/month) or higher
3. Click "Create Database"
4. **Important**: Render's PostgreSQL 16 includes pgvector by default!

### Step 2: Create Redis Instance

1. Click "New" → "Redis"
2. Configure:
   - **Name**: `chatwoot-redis`
   - **Region**: Same as PostgreSQL
   - **Plan**: Starter ($7/month) or higher
3. Click "Create Redis"

### Step 3: Create Web Service

1. Click "New" → "Web Service"
2. Connect your GitHub repository
3. Configure:
   - **Name**: `chatwoot-web`
   - **Runtime**: Docker
   - **Dockerfile Path**: `./Dockerfile.render`
   - **Plan**: Starter ($7/month) or higher
4. Add environment variables (see section below)
5. Click "Create Web Service"

### Step 4: Create Worker Service

1. Click "New" → "Background Worker"
2. Connect the same GitHub repository
3. Configure:
   - **Name**: `chatwoot-worker`
   - **Runtime**: Docker
   - **Dockerfile Path**: `./Dockerfile.render`
   - **Start Command**: `bundle exec sidekiq -C config/sidekiq.yml`
   - **Plan**: Starter ($7/month) or higher
4. Add the same environment variables as web service
5. Click "Create Background Worker"

## Environment Variables

### Required Variables

```bash
# Application
RAILS_ENV=production
NODE_ENV=production
INSTALLATION_ENV=render
RAILS_LOG_TO_STDOUT=true
RAILS_SERVE_STATIC_FILES=true
SECRET_KEY_BASE=<generate-with-rails-secret>
FRONTEND_URL=https://your-app-name.onrender.com

# Database (auto-generated by Render)
DATABASE_URL=<from-postgresql-service>

# Redis (auto-generated by Render)
REDIS_URL=<from-redis-service>

# Email Configuration
MAILER_SENDER_EMAIL=noreply@yourdomain.com
SMTP_DOMAIN=yourdomain.com
SMTP_ADDRESS=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your-email@gmail.com
SMTP_PASSWORD=your-app-password
SMTP_AUTHENTICATION=plain
SMTP_ENABLE_STARTTLS_AUTO=true
```

### Optional Variables

```bash
# Features
ENABLE_ACCOUNT_SIGNUP=false
DEFAULT_LOCALE=en
FORCE_SSL=true

# Storage (default: local)
ACTIVE_STORAGE_SERVICE=local

# For AWS S3 storage (optional)
# AWS_ACCESS_KEY_ID=your-key
# AWS_SECRET_ACCESS_KEY=your-secret
# AWS_REGION=us-east-1
# AWS_S3_BUCKET_NAME=your-bucket
```

## Email Configuration

### Gmail Setup

1. Enable 2-factor authentication on your Gmail account
2. Generate an App Password:
   - Go to Google Account settings
   - Security → 2-Step Verification → App passwords
   - Generate password for "Mail"
3. Use the generated password as `SMTP_PASSWORD`

### Other Email Providers

**SendGrid:**
```bash
SMTP_ADDRESS=smtp.sendgrid.net
SMTP_PORT=587
SMTP_USERNAME=apikey
SMTP_PASSWORD=your-sendgrid-api-key
```

**Mailgun:**
```bash
SMTP_ADDRESS=smtp.mailgun.org
SMTP_PORT=587
SMTP_USERNAME=your-mailgun-username
SMTP_PASSWORD=your-mailgun-password
```

## Custom Domain Setup

1. In your web service settings, go to "Custom Domains"
2. Add your domain (e.g., `chat.yourdomain.com`)
3. Update your DNS with the provided CNAME record
4. Update `FRONTEND_URL` environment variable to your custom domain

## Scaling and Performance

### Vertical Scaling
- **Starter**: 0.5 CPU, 512 MB RAM - Good for testing
- **Standard**: 1 CPU, 2 GB RAM - Recommended for production
- **Pro**: 2 CPU, 4 GB RAM - For high traffic

### Horizontal Scaling
- Web service: Can run multiple instances
- Worker service: Can run multiple instances for background jobs
- Database: Managed by Render, automatic backups

## Monitoring and Logs

### Health Checks
- Render automatically monitors your app
- Health check endpoint: `/` (root path)
- Automatic restarts on failures

### Viewing Logs
1. Go to your service in Render Dashboard
2. Click "Logs" tab
3. Real-time log streaming available

### Key Log Messages
- `✅ pgvector extension is available!` - AI features enabled
- `⚠️ AI features will be disabled` - pgvector not available
- `🚀 Starting Chatwoot on Render...` - Service starting
- `Database initialization completed!` - Setup successful

## Troubleshooting

### Common Issues

**1. Database Connection Errors**
```bash
# Check DATABASE_URL format
echo $DATABASE_URL
# Should be: postgres://user:pass@host:port/dbname
```

**2. pgvector Extension Issues**
```bash
# Connect to database and check
psql $DATABASE_URL -c "SELECT * FROM pg_available_extensions WHERE name = 'vector';"
```

**3. Email Not Working**
- Verify SMTP credentials
- Check firewall/security settings
- Test with a simple email service first

**4. Assets Not Loading**
- Ensure `RAILS_SERVE_STATIC_FILES=true`
- Check `FRONTEND_URL` matches your domain

### Getting Help

1. Check service logs in Render Dashboard
2. Review environment variables
3. Test database connectivity
4. Verify email configuration

## Migration from Railway

If you're migrating from Railway:

### Step 1: Export Data (Optional)
```bash
# Connect to Railway database
railway connect postgres

# Export data
pg_dump $DATABASE_URL > chatwoot_backup.sql
```

### Step 2: Deploy to Render
Follow the deployment steps above

### Step 3: Import Data (Optional)
```bash
# Import to Render database
psql $RENDER_DATABASE_URL < chatwoot_backup.sql
```

### Step 4: Update DNS
Point your domain to the new Render service
